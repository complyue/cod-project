## Structural regions

`region` declares a product of named fields. A consumer can require a compatible field subset; WPO retains the concrete region layout, including additional fields and their actual offsets. Field names, val/ref/ptr kinds and data/UoM identities remain significant. Structural compatibility neither creates an owner nor converts one actual region into another. A requirement is a lower bound, not an access view that hides extra concrete fields.

Unmodified/val fields store bits directly; ref/ptr fields store same-owner references. Capturing a val slot observes its current bits. Capturing a ref/ptr slot observes its current binding and later rebinding, with ordinary initialization and checked-NPE obligations. Region-level allocation/release remains intrinsic; free lists, pools and item reuse remain library policies. No physical allocator or relative-pointer encoding change follows.

H-361/H-362 and [D-17](ExceptionControl.md) require explicit `return` for values from proc/func brace bodies. Return from deferred catch/finally targets the enclosing callable, replaces a pending completion and continues remaining cleanup. Missing a required return is unchecked, with static diagnostics where possible; void callables may fall through. H-363 records pure declarations with implicit body results while deferring purity implementation. Explicit returns and missing-return delivery are implemented; executable fixtures use the explicit source surface. Deferred registration and handler execution remain outstanding. These source changes preserve complete values, caller result storage and owner/access checks.

## Ordinary aliases

```text
[const] [val | ref | ptr] var name [: [const] Type] [in owner] -> lvalue
```

An alias selects existing storage once. It creates no holder, allocation, payload copy or ownership transfer. Omitted kind is inferred; an explicit prefix must match exactly. A ptr field remains ptr even when currently non-null. An optional type annotation checks the selected view without numeric conversion. `:const` is also valid without an explicit type.

`in owner` checks the storage's actual owner. Declaration-leading `const` restricts the selected binding/storage through the alias; type-leading `const` restricts its target and every derived access path. These dimensions are independent under D-14; other writable aliases can still change the storage. Existing `=`, `<-`, `<=>` and `<->` rules apply through either name. Selecting an array element or field path fixes that storage location, rather than re-evaluating the selection later.

Aliases can name ordinary variables, regional fields and addressable array elements. Whole-region holders, TLS bindings, temporaries and non-addressable logical container elements do not supply this alias form. Selecting a field through a dynamic region resource does not alias its TLS binding. A lexical pointer into a region still has lexical binding storage and is ineligible for closure capture.

## Callable owners and captures

| Syntax | Meaning |
| --- | --- |
| `where {region state:Counter}` | Declare a formal regional owner and its required field shape. |
| `func()->const u64 with {region state}` | Associate a callable with that actual owner. |
| `func [ticks] () -> const u64 { return ticks; }` | Declare the complete body capture list. |
| `func () -> const u64 { return ticks; }` | Infer required body captures. |

```text
data Stream { id:u64; }
region Counter { ticks:u64; }
function reader(ref stream:Stream in state)
    where {region state:Counter}
    -> func()->const u64 with {region state} {
    val var ticks:u64 in state -> state.ticks;
    return func [ticks] () -> const u64 { return ticks; };
}
```

The stream argument supplies its actual region owner; a separate region parameter is unnecessary. The alias selects a regional slot, so the callback can outlive the factory call while that region remains live. It does not retain the factory's lexical alias cell. Named and anonymous functions/procedures share these capture rules.

Omitted brackets infer required variables. An explicit list must include every required capture: missing entries error, unused entries warn. Every listed capture remains retained, even if unused. Its owner must appear in with before any unused warning is considered. Every with-listed owner must actually be captured; the list is not a conservative lifetime upper bound.

Captures may retain regional slots, borrowed regional access and statically known callables with valid dependencies. Ordinary lexical val/ref/ptr binding cells cannot be promoted or captured. Captures do not freeze regional contents or extend owner lifetimes. Functions remain independent of dynamic effects; procedure lexical captures remain separate from perform's captured symbolic values and behave/direct calls' current dynamic context.

Parentheses group callable types. `-> func()->T with {...} throws E` declares the returned callback's exception, while `-> (func()->T with {...}) throws E` declares the factory's exception. Unbound with names reject; with does not declare a new owner.

## Owner projection

`cb -> state` borrows the region named state in cb's visible with-type, retaining the captured permissions. A helper accepting `func()->const u64 with {region r}` projects `cb -> r`; the factory's former name state is not exposed through that parameter. Multiple names map explicitly to actual regions, independently of declaration or allocation order.

Projection permits ordinary region helpers and root-field access. It cannot consume ownership, obtain writable access from a readonly association or outlive the region. Each owner association is a logical environment slot; WPO may eliminate its physical storage when the actual region is statically fixed. No separate lookup service or RTTI is required.

## Runtime callable contract

A callable view preserves its selected family dispatcher, module interpretation, view contract and required runtime environment. Several methods are permitted; actual argument types choose the applicable method. Existing native body-selection adapters are implementation infrastructure, not proof of family dispatch across abstract argument/result types. Direct method selection is valid when equivalent for all admitted alternatives. The family architecture and WPO coverage are tracked in [D-21](AheadOfTimeMultipleDispatch.md).

Module method registration constructs semantic information and does not capture runtime TLS. Runtime callable materialization creates the complete environment; reinstallation retains the existing value/captures. Lexical slots, named retained owners, nullable views, copies/replacement and captured/current invocation retain their qualified constraints. Per-family capture construction and abstract evidence must satisfy those constraints rather than introducing implicit owner extension or regional callable storage.

Method calls and callable-value calls separate operand preparation from invocation. Preparation retains the selected code, declared passing modes and ordered conversions. Invocation revalidates the prepared views and supplies the current procedure environment, or the explicitly requested captured environment. Symbolic builtins use the same boundary; their observable action occurs only at invocation. Native callable target protection and prepared-value cleanup retain their existing failure behavior. Scope-owned deferred registration and dispatch remain implementation work.

[Qualifier validation](../tests/cod/language/qualifier-validation.json) covers independent alias permissions, readonly field captures, const holder invocation/copying, copy-failure preservation and allocation-free repeated calls under [K-527](DesignAuthorityRegistry.md#k-527). Target access remains separate from holder binding permissions and pure behavior.

The ABI belongs to one statically linked CoD binary image. Compiler-generated typed adapters connect a callable view to its implementation and captured environment while preserving that implementation's module world. Native dependencies retain the system CRT contract. Cross-process code references, persisted callable views, dynamic code loading and general RTTI are outside this increment.

Callable view payloads and their environments have lexical lifetime owners. Their physical backing may be stack or heap; runtime-sized environments are supported. The owning scope must release its allocations on normal and exceptional exit. Allocation failure follows the existing unchecked OutOfMemory contract. They cannot appear in regional fields or arrays and are not bits payloads eligible for arbitrary transfer. Regions remain relocatable; a regional ADT and its methods provide the business-level equivalent of a functor without storing a native code address in regional data.

Non-null variables use func/proc and have val semantics; nullable references to callable payloads use ptr. Definitions establish callable identities/methods; callable variable declarations construct lexical values:

```text
func read = reader(state);
func copied = read;
copied <- another;
proc update = updater(state);
ptr optional:func()->const u64 with {region state} = null;
```

The initializer is evaluated once. A fresh callable result constructs its complete payload and environment into caller-provided lexical storage. At the internal ABI boundary, a callable-returning function/procedure receives a hidden destination pointer; a forwarding call may pass that destination onward. Merely returning a header pointing into an expired callee environment is invalid. Captured regions remain borrowed and retain their original lifetimes and access permissions.

Declaration and nested capture copy the complete selected callable value, including its environment. A wrapper retains an independent callable snapshot; replacing the original later does not change that snapshot. Regional slots and regions inside either environment remain borrowed, so their subsequent content changes stay observable. No regional object is copied and no lifetime is extended.

A default callable parameter has an independent callee-local target, following D-14's default parameter ownership. Its value is prepared at that argument's evaluation boundary, before later arguments can replace the source holder. An explicit `in O` parameter borrows external callable storage instead. A callable value result constructs an independent complete value; an explicitly borrowed result retains its declared external owner. Fresh unaliased images may transfer into their destination without copying. Allocation failure and later-argument failure must release prepared values without altering the source holder or extending captured-region lifetimes.

`destination <- source` replaces a compatible callable value in existing lexical storage, preserving type/owner checks. Ordinary `destination = source` cannot rebind a func/proc variable. A ptr instead refers to callable storage and uses ordinary nullable-reference rebinding/lifetime rules. Its invocation reads the currently stored callable value. typeof is compile-time only; isnull and checked NPE apply to nullable references.

The complete callable representation must remain valid after bits movement: it contains no pointers into its own prior storage or an expired factory frame. Nested callable environments are included by value. This is an intrinsic lexical value category, not a general bits type that may enter regional fields/arrays. The adapter computes environment access from the current payload address; a copied header pointing to a previous lexical environment does not satisfy this contract.

Direct/behave procedure calls use current dynamic bindings; perform installs the selected procedure's captured symbolic values for its execution scope. Native representation must not merge bodies, module contexts or captured snapshots merely because signatures match.

Recursive calls are required for both functions and procedures. A blanket recursion rejection is not an acceptable endpoint. Call checking must account for cycles in the demanded program; successful finite source expansion is not a substitute for native recursion. The deferred const-function/TCO plan in [D-19](ConstFunctionsAndTailCalls.md) does not restrict procedure recursion. Material conflicts with that plan require human review.

## LLVM compilation scale

Reasonable performance is a development requirement, including during the prototype stage. An MVP may narrow the implemented surface, but each implemented path must preserve the business contract and have defensible runtime and compilation costs. Measurements must distinguish construction and complete-value copying from invocation, expose allocation and cleanup behavior, and include shared/deep composition. Passing a convenient demonstration does not establish generality or scalability. No numeric performance budget or particular optimizer/allocator is selected by this requirement.

WPO determines the demanded program and its semantic contexts; it does not require one indivisible LLVM optimization unit. Native function boundaries must represent recursive cycles and shared dependencies without expanding the dynamic call tree into source copies. Reuse must preserve the selected module world, concrete signature, conformance information and captured context. A shared origin or matching signature alone is insufficient.

The prototype emits one program LLVM module and a separate native-service translation unit. It reuses checked, closed scalar function and callable-factory specializations within matching semantic views. Repeated pure record-return calls within one native caller can share a checked adapter when the reaching implementations, type, actual owners, access, initialization and conformance context agree. The lexical context is supplied at each call; the returned region address and runtime effects are never cached. Factory reuse also checks actual owners, callable argument alternatives and access; matching source names or result signatures alone do not justify sharing. It emits textual IR only when requested, emits bitcode for execution or requested artifacts, and releases serialized copies before native optimization. Runtime loops remain LLVM loops. Function/IR counts, frontend cost and native optimization cost must be assessed separately on shared and deep graphs; this is not evidence that arbitrary large programs fit one module. Physical partitioning and cross-partition optimization policy remain future implementation work, with the callable ABI retaining explicit call/environment boundaries.

Procedure images support captured dynamic bits, borrowed whole regions, regional object references, compiler builtin procedures and non-null native procedure values. A complete image contains retained regional addresses and inline nested images addressed by offsets. A concrete non-contextual function carries its typed entry address; generic, higher-order, regional-parameter and procedural images use an internal body/layout key selecting a checked adapter for the invocation context. Procedures additionally carry typed dynamic payloads, borrowed regional bases and demanded procedural snapshots. Complete-value copies are independent; invocation loads the selected entry, retaining a complete temporary image when replacement can invalidate its captures. A lexical holder owns the image and nullable pointers refer to that holder. Replacement constructs the new image before releasing the old one, preserving the old value on allocation failure. Reaching callable values follow control-flow joins and holder aliases; copied captures retain their selected alternatives rather than later holder replacements.

Default-local quantity arguments retain the selected source method's starred-parameter and preferred-route declarations. Each conversion finishes before the next argument executes; a failed conversion prevents later argument effects. The conversion graph comes from the calling module, while route aliases retain their defining module's unit identities. Direct-route priority, ambiguity warnings and whole-type lossless widening follow D-11. Every reaching body must accept the supplied conversion, including bodies reached through later loop iterations. Compiler-generated adapters select the appropriate conversion using the existing callable body key; they introduce no runtime unit tags, conversion registry or extra callable image. Checked conversion failures require the original call site's handler or throws declaration.

Generic invocation infers concrete types from arguments, checks repeated-variable agreement and declared bounds, and specializes the selected body in its retained module context. Passing or returning an already inferred generic callable preserves that value's own binders. Variadic callable parameters own independent local images. Dynamic pack indexing selects a holder under a common live lexical owner; subsequent indexed replacement uses complete-value transfer and participates in invocation-lifetime checking. An empty pack is valid in a zero-iteration traversal; an executed out-of-bounds access still fails.

Borrowed whole-region arguments retain their concrete root layout, actual owner, access and conformance information at each checked call. The native adapter receives the region address without moving ownership or extending its lifetime. Structural root requirements can admit extra fields while preserving their actual offsets. Direct named regional helpers use the same adapter mechanism. Recursive reuse must preserve each parameter's actual region/access relation; matching root shapes alone are insufficient. Later argument evaluation cannot leave an earlier borrowed input pointing into a released region.

An external-storage parameter receives the selected target's address, preserving the caller's storage and its current contents. Repeated occurrences of one owner variable must denote the same actual region or lexical scope; separate owner variables permit either equal or different owners. Region-specific binders additionally check the concrete root requirement and provide the body with borrowed regional access. Readonly inputs cannot satisfy writable parameters. Explicit ptr parameters forward nullable targets without reading them; isnull observes the reference, while an actual dereference retains its checked-NPE and initialization obligations. Null does not waive owner or access checks. Native recursive reuse retains provenance, access, conformance, nullability and scalar initialization facts. Ordinary result-view provenance is not replaced by a bits copy; owner-bound callable factories retain their body-aware return-owner checking path.

An explicit non-null scalar result `-> T in O` returns the target address through the native ABI. The caller retains the declared region or lexical owner and the signature's access permission. Every returning implementation must prove that owner and permission; callee-local targets cannot escape. The view observes subsequent writes to its source storage, survives release of a temporary callable image and never extends the source owner's lifetime. Ordinary `-> const T` bits results remain independent values.

An explicit nullable scalar result `-> ptr T in O` returns an address without reading its target. It retains the declared owner, access and possible input-storage initialization dependencies. Forwarding an uninitialized target does not initialize it, and a later read must still be proved valid. Native calls carry compiler-only initialization evidence for borrowed local storage. Every reaching implementation and every applicable normal or exceptional exit contributes to the proof. Initialization follows the target allocation across aliases and native calls. Recursive reuse preserves the same live targets and their established contents; a changed target or alias relationship requires its own checking. A returning recursive cycle does not enumerate its possible call paths. Passing a target to a writer need not read its old payload. By-value arguments and indices retain their evaluation-time read obligations, so a later argument write cannot justify an earlier uninitialized read. Exceptional return evidence retains writes that occurred before the failure, without assuming normal-return writes occurred. General loop-carried pointer-target analysis remains separate.

Dynamic indexing of an external-owner variadic pack selects a target view before any payload read. Its elements must share a live owner; the selected view conservatively retains their access, nullable and initialization obligations. Thus isnull can inspect an indexed nullable argument without dereferencing other elements. Ordinary local-value packs still select values. Empty numeric and callable borrowed packs permit zero-iteration traversal; an executed access fails its bounds check.

Borrowed callable inputs pass their holder addresses. Later argument evaluation may replace a holder's value; the callee observes the value stored there when it reads. The borrow does not copy the image, transfer ownership or extend the holder's lifetime. Assigning that input to a func/proc variable constructs an independent complete value, including when the supplying argument was a fresh temporary or an indexed variadic argument. Nullable pack selection retains a view without dereferencing other elements.

A callable result with an explicit external owner, such as `-> (func()->const u64) in O`, returns a holder view. The native success result carries its address without a fresh-result destination or image copy. Conditional, catch and recursive paths retain the selected holder identities. A later replacement of that holder remains observable, and writes through a permitted returned view update the same holder. `-> ptr (func()->const u64) in O` permits null; a const qualifier restricts access. Every path must preserve the declared owner, access and retained-region validity. A callee-local callable cannot satisfy an external borrowed-result contract.

The caller reconstructs its region-relative view using the declared actual owner; it retains the array identity, scalar element/index types and access qualifier. No array header or elements are copied, and the view does not extend the region lifetime. `-> ptr Values in r` forwards nullable views; isnull observes absence and dereferencing requires the existing checked-NPE handling. Every implementation must return storage belonging to r. Generic, recursive and procedure calls use the same borrowed-result ABI; perform and behave retain their captured/current dynamic contexts.

A structural root requirement is a field subset, so field access uses the checked body's actual concrete layout. Selected interface facts must hold across every reaching returning implementation, including loop replacements, conditional joins and recursive exits. Deferred return facts are resolved before dependent method selection; an owner argument alone cannot establish them. Recursive/shared return graphs preserve common evidence without expanding all paths. Nullable results, generic forwarding and procedure captures retain the ordinary borrowed-result rules. Different-concrete abstract results and broader result-dependent dispatch cycles remain separate implementation/design boundaries below; no runtime type discriminator or region layout change is introduced.

The caller retains that region's concrete root layout and the common interface facts established by the checked returning implementations. Structural subset requirements do not hide extra fields or change their offsets. A consumed caller name stays unavailable. ### D18-Q-result-discrimination — behavior confirmed; representation pending-human

An abstract result can hide different concrete types: callbacks returning `Entity in r` can return Node or Edge. H-375 requires subsequent calls to retain actual-type method selection, answering H-251’s behavioral question. A one-concrete-result implementation limit cannot be a language restriction. H-376 requires precompiled coverage of the admitted alternatives.

Concrete evidence could accompany a lexical view or use another qualified representation, but no physical choice is made here. The design must trace evidence through parameters/results, stored and nullable references, TLS, callable environments and owner-preserving relocation; result destinations and exceptional cleanup remain constraints. A discriminator is not automatically a reflection catalog or a regional object-header tag. The current record path’s single-layout metadata cannot implement different-concrete results by returning only an address and an abstract declared type. DD-AOT-05/06 covers this required mechanism work; actual-owner union policy remains independent.
