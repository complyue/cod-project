## Before coding

Start with the intended idiomatic source and the real acceptance workload. Include the smallest coherent seed increment needed to express that source under confirmed language contracts. Use the intended source for delivery and keep temporary substitutes isolated. Send the proposed structure to the CoD design discussion and obtain explicit clearance for the identified batch before writing new code. Include tests, scripts, native glue, tooling and new code inside existing files. State which caller enters the operation, who owns its state, how results cross the boundary and what happens on failure. Group related changes that can be reviewed together. Work within a cleared proposal can proceed as one batch. Return to review before expanding it. An existing implementation, language qualification or retrospective disposition does not preapprove later additions. The design discussion settles questions within the user's principles and brings material trade-offs to the user.

### Read-only Boolean observation in the seed checker

In [the seed checker](../cod/lang_checked.hh), `snapshot_boolean` asks which path conditions accompany each Boolean result in a supplied `LexicalState`. Both call preparation and completion summaries consume this evidence. One private helper may project it from the supplied state. Reuse the existing `path_conditions`, the present or absent facts for the current versions of definitely non-null or definitely null bindings, and the existing insertion and normalization of `ConditionFacts`. The exploring fallback applies the same projection to each state reached by `predicate_paths`. Branch refinement keeps its current join, reachability and condition rules.

Select the observational path before taking any full-state snapshot. A dead input produces no outcomes. A live input with no predicate admits both truth values. For a predicate with an empty `results` map and `complete_results == false`, plain presence admits both, either constant admits its stated value, and abrupt completion admits neither. Admit the projection only for these cases. A complete result map can exclude a truth even when it has no entry for that truth. Null tests, compositions and proofs carrying result clauses retain the existing exploration. Use the supplied state even when it differs from the checker's current frame. Preserve the input and the checker's state across every observation. Any loop that enumerates state owned by the checker needs a stable input while the fallback temporarily replaces that state.

Verify equality of the complete normalized `BooleanValue` against the existing exploring computation on identical inputs, including liveness, both constants, unrestricted presence, versioned nullable bindings, and conditions tied to initialization or a selected target. Cover absent outcome keys, empty clause sets and an unconditional clause, and exercise a constrained presence or constant with a complete result set. Run direct call, rebinding and cleanup cases in both seed modes, preserving their accepted results and rejection of unsafe reads. Measure the actual typed CompilerCLI with the same source, mode, configuration and host before attributing a speed improvement. Its generated providers, linked object, rejections and cleanup still require the [single-file workload](../applications/cod-booter/docs/ModuleGraph.md#single-file-object-route). Changes to general predicate solving, the representation of mutable state, or the completion solver require separate review.

### Writable supplier-array access

For the [path-key consumer](../applications/cod-booter/docs/ModuleGraph.md#writing-canonical-key-bytes-from-a-supplied-here-body), change the seed checker’s ordinary supplied-`here` admission and its direct fixtures. Admit a live, unambiguously identified lexical ref slot selecting a definitely initialized nonnull named array of admitted bits elements with writable target access and one proven live target owner. Preserve that proof for every admitted invocation. Record the slot as a live binding with its place and target owners. The existing emitter passes the slot, and the wrapper’s native callback forwards the original `work` activation. Direct native access to a writable supplier place and callback-side holder rebinding have separate implementation scopes.

Completed element writes must be visible through other live references on normal and protected exits. Any check that relies on a possibly overwritten element’s former value must account for the write. Zero invocations establish no write. Where the seed admits an independent same-owner rebind between invocations, verify that the second invocation writes the new target. If that source is outside the seed profile, record the exact rejection and inspect the generated slot load as structural evidence. The real public-wrapper byte transfer and nested restoration still require execution.

### Lexical backing for the indexed AST array

For the [initialized slot array](../applications/cod-booter/docs/ModuleGraph.md#first-indexed-ast-path), generated code may request an aligned byte extent through one private operation in [the shared runtime header](../cod/runtime/cod_lang_runtime.h) and [its C implementation](../cod/runtime/cod_lang_runtime.c). The caller supplies the cleanup-list address of the actual lexical owner selected for placement, the checked byte size and the element alignment for the compilation target. A nested caller allocating in an outer lexical owner must supply the outer list. Named-region placement follows its own allocation path.

Use the existing [raw storage service](../include/cod_region_storage.h) and lexical list's release callback. Check representability before narrowing, and honor the service's power-of-two alignment limit through `max_align_t` on the executing target. Lowering must diagnose an unsupported element layout before emitting this call. For zero logical bytes the service can use minimum backing. Acquire the cleanup record and backing before linking either into the list. On acquisition failure, release any partial acquisition and leave the list as it was. On success, the registered callback releases the backing and cleanup record exactly once during owner teardown, after its deferred actions finish.

The seed keeps length and fill evaluation, layout, typed stores and publication under the existing array contract. Successful acquisition gives the lexical owner responsibility for the backing even if a subsequent initialization or table replacement fails. Readers retain the preceding published table until a complete replacement is installed. Verify zero length with an observable fill, aligned slots, partial acquisition failure, and a deferred read of the previous table after failed growth. Verify that an outer-owned extent survives inner teardown and releases once on exit, alongside existing text or builder allocations. These checks supplement the real parser-to-object acceptance.
