Receiver and forwarding calls use the supplied body’s executable outcomes when the body is known. A protected transfer runs receiver cleanup. Receiver catches handle their own ordinary failures. An escaping failure from a group-local finally cancels the pending outward return or break. A catch outside that finally can then resume the group. Each ref input proves a fixed actual owner from an ordinary borrowed receiver argument or the producer activation (`in here`). Forwarding preserves the established owner. Admitted named ordinary operands prepare in written order. [Shared receiving header](../../../design/RangedForAndGenerators.md#one-receiving-header-for-both-call-forms), [Borrowed yields and owner scope](../../../design/RangedForAndGenerators.md#borrowed-yields-and-owner-scope)

  `typeof` can inspect a direct named call with scalar arguments and a supplied `here` body. A module-supplied body has procedure permissions, and one supplied inside a function uses that function's permissions. [Named terminal contract](../../../design/ProducersAndTransformers.md#a-named-terminal-consumer)

  A direct generator or forwarded producer can attach through `!>` or `<!` to one or more direct named stages when the expression supplies a named terminal or explicit receiving body. Builtin `|>` and `<|` connect stages in traversal order. The checker prepares ordinary operands and bounded source operands in written order, including parenthesized groups of mixed directions. Each stage opens its upstream on demand and can reuse the prepared operands on repeated openings. Labelled offers, Boolean feedback, checked failure propagation and owner-checked readonly handoffs cross the connected stages. [Processor composition and attachment](../../../design/ProducersAndTransformers.md#processor-composition-and-source-attachment)

[Lexical pipeline storage](../../../design/ProducersAndTransformers.md#lexical-variables-for-open-pipelines)
