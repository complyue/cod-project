## Current implementation boundary

The source compiler implements primitive scalar and bounded intrinsic-exception values. LLVM-independent checking selects semantic methods and completes demanded scalar obligations before native emission. Proven calls select prepared specializations; general bodies retain independent local operation choices. Concrete methods reuse one native implementation. There is no legacy fallback.

Supported source includes explicit const scalar results, void callables, unbounded scalar type parameters, exact-argument overload selection with same-T relations, direct/mutual recursion, conditionals, short-circuit booleans, primitive numeric operations and widening, and selected `std:io` printing. Ordinary grouping shares the enclosing cleanup scope; explicit `{{ ... }}` ends its own scope. Plain deferred calls prepare scalar arguments before registration and run in reverse registration order on normal return or failure. Value-callable fallthrough warns and raises unchecked `MissingReturnException`.

Local scalar `val` declarations provide independent storage. Default and explicit scalar parameters receive callee-local copies; writable parameters and values accept `<-` updates. Declaration-leading const protects val payloads, type-leading const restricts target access, and transfer results are readonly destination views. Grouped declarations preserve source order and initializer-before-binding lookup. Explicit scopes restore outer names; ordinary groups share names and reject duplicates. `-Wshadow` has its own error control.

A `val` may use `make local T` without an initializer and receive a later write. Reads require definite availability and initialization across conservative branch and short-circuit joins. `make local typeof(name)` queries a known local type without reading its payload. `=` on existing val storage remains an error because val has no reference binding to replace. Unsupported reference, capture or owner operations do not fall back to bits copying.

Local ref/ptr declarations can refer to checked live scalar or intrinsic-exception targets. Bindings have distinct availability and access permissions; aliases share the target's type, owner and initialization facts. A ref requires initialized storage. A non-null ptr may name an uninitialized destination and initialize it with `<-`. Declaration-leading const forbids rebinding without preventing writes to a writable target. Inferred readonly access stays readonly, and an explicit writable target annotation cannot strengthen a readonly source. Borrowed targets require the exact declared type; independent copies may use ordinary bits widening.

Fresh bits initializers and declaration `<-` create independent lexical storage. Initializing from an existing view retains that storage, including its original owner. Initializer effects execute once even when no payload read or copy is needed. Explicit scopes cannot export an ended target; a local alias does not extend an owner or bypass loop-control capture restrictions. Writes through either name participate in the same branch, loop and cleanup initialization equations. Aliases of caught exception values use the existing immutable capture mechanism. Reference slots carry execution-local addresses without a separate heap allocation.

`ptr p:T = null` records a target type without allocating payload storage or inventing an owner. A first non-null target establishes the owner; clearing the pointer retains it. An alias or assignment from an already owned null view also retains that owner. Incompatible owner paths and access after owner expiry are rejected. Repeated iteration scopes represent distinct owners: an outer pointer cannot acquire a fresh iteration owner on each pass. A per-iteration pointer can use its own explicit scope.

`isnull` evaluates a reference view once without loading its payload. Stable tests refine the corresponding branch, including short-circuit expressions; changing the selection invalidates that proof. A ref requires a proven non-null initialized target. Potentially null reads and writes require a covering catch or the immediate callable's `throws NullPointerException`; module code must catch explicitly. A write checks its selected destination before RHS effects. Discarded rebinding and null tests do not dereference, whereas copying an argument or consuming an assignment result does. Nullness, initialization and valid owner lifetime remain independent. `typeof(isnull(name))` and `typeof(isnull(null))` can supply the bool type to `make local` without runtime evaluation.

Reference `=` selects an existing target of the exact declared type and initializer-fixed owner. It preserves destination access; readonly sources cannot enter writable bindings, and const bindings reject rebinding. A ref requires an initialized new target. A discarded ptr assignment need not read the new payload; using its result as a value does. Conditional, ordinary/explicit scope and guarded expressions can select target views. Scope/finally cleanup preserves the address selected by the expression before cleanup. `<-` likewise captures its destination address before RHS effects, so an RHS rebind cannot redirect that write.

Finite target discovery precedes initialization checking within each demanded scalar instance. Sequential/branch facts retain reaching targets; repeated loops and cleanup conservatively account for later target changes. Literal zero/single-iteration ranges retain their simpler flow. Reads require initialized possible targets or a valid guarantee for the current selected target. A write through a selected pointer can establish that guarantee without marking all candidate allocations initialized. Rebinding invalidates the guarantee; target versions distinguish a changed selection even when its possible-target set is unchanged. Stable aliases can retain their selected-target guarantee. Native address slots remain separate from source scalar payloads and the private call/exception carrier.

The target catalogue is conservative across mutation boundaries. Future assignments and correlated selections can enlarge its sets; complete alias-history, predicate and queue/category-sensitive mutation proofs remain unavailable. Cleanup equations retain allocation-specific initialization guarantees; a write through multiple possible targets does not yet export a selected-target guarantee across an arbitrary deferred queue. These are proof limits, not additional source owner or initialization rules.

An explicit `in O` parameter with `where {owner O}` borrows an existing live scalar target. Repeated O occurrences require the same actual owner; distinct owner variables allow equal or different owners. Owner names are implicit const lexical bindings, with no scalar payload or extra region capability. Writable parameters require writable targets. Callee reference rebinding changes its local binding, while payload writes affect the caller's selected storage. Default parameters continue to copy into independent callee-local storage.

Borrowed arguments prepare their selected addresses once, in source order. An explicit ptr can forward an owned null view without a payload read. Ref requires a proven non-null initialized target; an omitted modifier retains the caller's ordinary read boundary, including checked NPE before later operands. A callee's ptr dereference retains its own checked obligation. Prepared deferred calls save the selected address and observe its payload at invocation; the owner must survive their cleanup scope. Failed preparation or registration does not invoke the callee.

Explicit external-owner results (`-> T in O`, `-> ref T in O`, or `-> ptr T in O`, with target const as applicable) preserve the returned address and access. Ptr results may be null; ref/default borrowed results require non-null initialized targets. Local/default-parameter storage cannot escape as an external result. Return, finally and deferred replacement preserve the selected address through remaining cleanup. An independent const result preserves its evaluated bits; copying a borrowed call result reads the target after callee cleanup. Named and mutual generic recursion reuse native methods without encoding actual owner identities in runtime arguments.

The bounded call proof currently requires initialized non-null borrowed targets and a known actual owner. Borrowed results conservatively include compatible argument targets from their declared owner. Initially uninitialized borrowed destinations need cross-call read/write summaries; ownerless inputs, borrowed exception upcasts, inferred result owners and owner-constrained overload ranking remain gaps. Families with differing argument-preparation modes and general bodies whose instances require different value/view result contracts or storage layouts report staging gaps before emission. The private native transport carries an execution-local address and target-type evidence in positions determined by the checked call contract. It introduces no source pointer arithmetic, runtime owner object, public ABI or persisted representation.

Half-open integer `for` and scalar `fold` evaluate bounds once. Bounds currently have matching primitive integer types; fold bodies retain the initial scalar type. The index and accumulator are readonly loop bindings. A range's optional `else` runs only for zero iterations and cannot access its index. Body and else are both checked; feasible normal paths determine post-loop initialization, with literal integer bounds providing empty/nonempty facts. Direct body/else declarations require a nested explicit scope.

Ordinary loop bodies register plain deferred calls to the nearest full scope. Each successful registration owns independent prepared scalar arguments and joins one dynamic LIFO queue. Explicit scopes inside loops drain per iteration; scopes surrounding loops accumulate until exit. Failed preparation registers no action. Allocation failure preserves earlier actions; invocation failure replaces the pending failure while remaining actions run. Execution-local records use the native allocator and are released exactly once. Storage grows with live registrations and argument arity; no regional storage, persistent representation or owning-reference behavior follows from this scalar queue.

`try { ... } finally { ... }` preserves an expression's value or pending return/failure through unconditional cleanup. A finalizer completes with void or explicitly returns from the enclosing callable; a new return/failure replaces the pending completion. Ordinary grouping still creates no lifetime scope. Finally reads require initialization across the conservatively tracked normal, return and failure inputs.

`defer { ... }` resolves lexical bindings when registered and reads their contents when invoked. Its declarations require explicit nested scopes, and it cannot capture loop-control bindings. Delayed blocks may register more work and return from the enclosing callable while remaining actions continue. Attached `catch`/`finally` and bodyless `defer catch (...) { ... } finally { ... }` share ordinary guarded execution. A pending exception skips the attached body and enters a matching handler directly. Finally runs on every completion, and sibling handlers cannot catch each other's failures. A plain delayed block executes even during failure cleanup. Missing-return enforcement follows cleanup, so an explicit deferred return can supply the required result.

Deferred recovery preserves a retained normal scope value or enclosing return. Explicit returns from a deferred body, catch or finally replace the pending completion while remaining registrations still run. A handler's final expression is discarded; it cannot supply a missing callable return. When the scope body failed before producing a value, normal recovery produces void. A value-producing scope must have compatible normal results on every recovering path, or its handler must return explicitly. Ordinary catch recovery ends an interrupted return rather than resuming it.

Catch parameters are immutable exception bits. A delayed block that uses a caught value saves its own copy at registration, including the active exception for a bare rethrow. Repeated execution of one catch cannot overwrite an earlier registration's value. Nested registrations preserve those copies and their explicit causes. Unused caught values need no capture payload; ordinary mutable lexical values retain delayed reads. These copies grant no borrowed-storage or region lifetime extension.

Intrinsic exception types use explicit `std:exceptions` selections and aliases. Typed catches match exact categories; an untyped catch receives `SystemException`. Catches cannot catch failures from their sibling handlers. `throw value`, bare rethrow inside an active catch and `throw value from cause` preserve the bounded payload. Values can be copied into locals, passed to concrete/generic methods, returned and prepared for deferred calls. Passing an exact exception to a `SystemException` parameter preserves its category and details without implying a same-T relation between different arguments.

Exception fields `category`, `site`, `requested`, `available` and `cause_count` are readonly. `cause_at(value, index)` returns a retained cause; an invalid index is a terminating runtime check. Explicit cause construction creates an immutable relationship and may raise OOM. Ordinary raising, routing and copying require no exception allocation; a failed chain construction raises a fresh OOM without attaching either operand. Checked exception paths require a covering catch or an intrinsic `throws` declaration. Declared checked failures remain caller obligations even when a particular body does not raise them.

The private native value carrier includes bounded exception bits in programs that use them; primitive-only programs retain the smaller scalar carrier. Its tags, capacity and uniform transport overhead are implementation details, not source payload layouts or a public/persistent ABI. Cause and source-site handles are execution-local numeric identities, not native pointers.

The checker follows successful registrations through branch joins and loop backedges to their owning full scope. Finite completion equations compose normal flow, retained returns, terminal failures and intrinsic exception categories without unrolling runtime queue lengths. Preparation failure leaves the previous queue intact; nested registrations run before their predecessors. Checked deferred failures require a handler reached during invocation or an enclosing throws declaration. A catch surrounding registration alone supplies no invocation coverage.

Deferred reads require initialization on every reaching invocation path. Successful writes carry guarantees through registration choices, loop backedges, nested queues and normal/return/category-specific failure exits. A scope continuation or surrounding catch can use the guarantees of its reaching cleanup outcomes. A failed setter registration supplies no write, and a later write cannot justify an earlier read. Fresh action-local storage retains its own initialization obligation; no implicit zero value or runtime initialization flag is introduced. Registration never applies a delayed write immediately.

The initialization proof composes read requirements with completed writes. Branch-selected queues retain established facts; alternatives intersect their guarantees. Read requirements remain visible when a catch, finally or return replaces the pending completion. Missing-return warnings likewise use possible completion after cleanup and can still be conservative when wider relationships are unproved.

This is a closed source-program slice: there is no external abstract-value ingress. Execution-local scalar tags preserve the supported primitive identities but define no persistent ABI or CoD `<any>` representation. Generic checking retains finite demanded substitutions; runtime recursion and loop counts add no bodies. The implementation does not prove the full generic/recursive closure contract. Regional values, region-specific owner parameters, explicit owner annotations on local declarations, alias-slot declarations and swaps, module-local captures, runtime-selected reference-binding destinations, rebinding from fresh values, target-access-qualified overloads, units/fractions, first-class callables, dynamic binding and iteration effects, general module composition, mixed-type range bounds, fold accumulator conversions, generic typed catches, non-intrinsic throws and omitted-result inference remain explicit implementation gaps. Untyped null in a payload expression requires a typed ptr binding first; prepared `defer isnull(p)` is unavailable, while a deferred block can test its current view. No nullable-to-ref conversion syntax is selected beyond existing static proof. Call failures, common-exception results, mutable exception values after cleanup and category relationships through copied caught values can be conservative. Arbitrary predicate correlations, wider queue/input relationships and mutation summaries remain proof gaps; the current equations do not establish complete alias, owner or category-sensitive flow coverage.

Feature parity and a fully passing legacy suite are not acceptance conditions for this restructuring stage. Supported paths must still behave correctly; missing paths must not be reported as new language prohibitions.

The legacy fixtures and their assertions remain intact. They provide recovery/comparison evidence and target behavior as source capabilities are implemented. A passing historical report does not establish current compiler support. Focused source/native checks establish the supported foundation; historical legacy failures are not reclassified as passing.
