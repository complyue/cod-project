## Current direction

One cortical column (CC) occupies one region and represents an instantaneous semantic vector. CCs exchange vector sequences; the overall target is hundreds to tens of thousands of CCs. The current sizing case uses DeepSeek V4.1 Flash token embeddings. Exact checkpoint and tensor selection remain open.

Capacity planning comes first. Each CC must fit a Raspberry Pi-sized resource budget, and **the per-node RAM ceiling is 16 GB**. These are separate constraints: neither a fixed CC count per node nor an update rate has been selected.

The user directs the connectivity discussion toward HTM and observes that connections within a minicolumn are less necessary. The current direction budgets sparse contextual connections and column-local selection rules. H-13 introduces unequal connection capacity: more slots for highly connected neurons, fewer for lightly connected neurons, with training-driven migration between preallocated sets. H-14 fixes static pool allocation and one pointer from each neuron to its current out-of-line set; training and capacity migration use no heap allocation. H-15 keeps rare outgoing degrees around 10,000 in scope; the current Flash 60+60 case has 614,400 neurons. H-16/H-17 specify one set-to-source array and parallel four-byte target / one-byte weight arrays. H-18 prioritizes direct arithmetic indexing of a static pool; H-38 makes a total set count slightly above the neuron count the explicit sizing objective. H-39 excludes preserving an older scenario's connection capacity. H-19 sets the minimum capacity at 100, omits smaller classes and allows ignoring weakly connected outgoing participation. Widespread, useful underfilling would justify reconsidering the minimum. H-21 provisionally retains the alpha-near-3 class counts and opens the incoming-ownership discussion. Migration rules, signed encoding and recurrent dynamics remain open.

## Principle: requirements before auxiliary structures

Define the business requirement first, then discuss the implementation algorithm. Consider an auxiliary data structure only when that discussion establishes its purpose and necessity. Do not preselect supporting representations or reserve memory for hypothetical ones. Once justified and selected, document the structure and its cost under the existing static-allocation, SoA and alignment rules. Current capacity figures cover the named arrays only; algorithm-dependent storage remains unspecified.

H-27's current planning case is **DeepSeek-V4.1-Flash's 5,120 dimensions × (60 positive + 60 negative cells)**, giving **614,400 neurons**. The worked 15-class candidate uses the smallest exact-halving pool above N, with A=311296 sets in the 100-slot class, giving **622,573 sets**, **106,492,416 slots** and **540,174,772 bytes of per-CC arrays assuming two FP4 values per byte**, about **515.15 MiB**. It has 8,173 surplus sets (1.330241%); the [16-class candidate](ConnectivityScalingResearch.md#sizing-objective-and-class-count-options) has 6.665039% surplus, a maximum of 18,432 slots per set and 542.88 MiB of arrays. Neither class count is mandatory. The embedding table is shared once per node and excluded from the per-CC arrays (H-28). The [exact calculation](CapacityPlanning.md#flash-6060-calculation) states the sizing assumption and extra-state boundary. [Signed population encoding](SignedPopulationEncoding.md) covers the shared decoder/context questions and H-26's human-neuron-count reference; final pool size and neural dynamics remain open.

Capacity planning distinguishes reserved slots, retained edges, incoming degree and outgoing influence. Extra fixed sets can serve as migration destinations; they do not guarantee availability in every class. [Target-owned incoming sets](IncomingConnectivity.md) are the current recommendation for gather-based updates, under evaluation following H-21. This preserves five bytes per slot and the static budget, while changing which endpoint is stored in each slot and which degree the capacity law constrains. Historical snapshots and additional dynamics state have separate budgets.

The [scaling research](ConnectivityScalingResearch.md) separates capacity spacing from degree distributions. Adult-fly evidence reports outgoing exponent 2.96 and incoming exponent 3.15; neither establishes a universal human exponent. The provisional template is an engineering prior, not a fitted application histogram. The [current array formula](CapacityPlanning.md#exact-static-arrays) applies to either source- or target-owned sets without changing the payload budget.

[Input count and excitability](SynapticIntegrationResearch.md) separates anatomical contacts, distinct sources and coincident activity. Large incoming sets do not define a firing rule: a global sum with fixed positive weight scale and threshold can create degree-dependent activation bias. Dendritic integration and activity control remain explicit model choices.

H-23 regards smaller typical incoming weights at higher live degree as a reasonable modeling direction. H-24 assigns weight scale to [training strategy](SynapticIntegrationResearch.md#training-strategy-incoming-weight-scale), as a possible hyperparameter or dynamically planned/adapted quantity. The [allocation comparison](ConnectivityScalingResearch.md#incoming-and-outgoing-degree-parameters) distinguishes incoming/outgoing degree distributions from capacity spacing. Its adjacent-class ratios are calculated projections from fitted exponents and chosen geometry, not measured populations. The alpha=3 allocation remains provisional while 3.15 provides an incoming-tail comparison.
